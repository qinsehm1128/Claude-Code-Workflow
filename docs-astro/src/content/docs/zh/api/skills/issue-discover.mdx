# Issue Discover

统一的问题发现与创建。从 GitHub/文本创建问题，通过多视角分析发现问题，或进行 Prompt 驱动的迭代探索。触发关键词："issue:new"、"issue:discover"、"issue:discover-by-prompt"、"create issue"、"discover issues"、"find issues"。

## 概览

| 属性 | 值 |
|------|-----|
| **名称** | `issue-discover` |
| **工具** | `Task`, `AskUserQuestion`, `TodoWrite`, `Read`, `Write`, `Edit`, `Bash`, `Glob`, `Grep`, `Skill`, `mcp__ace-tool__search_context`, `mcp__exa__search` |

## 核心设计原则

1. **动作驱动路由**：AskUserQuestion 选择动作，然后加载单个阶段
2. **渐进式阶段加载**：只读取选定的阶段文档
3. **CLI 优先数据访问**：所有问题 CRUD 操作通过 `ccw issue` CLI 命令
4. **自动模式支持**：`-y` 标志跳过动作选择，自动检测

## 自动模式

当使用 `--yes` 或 `-y` 时：跳过动作选择，根据输入类型自动检测动作。

## 使用方法

```
Skill(skill="issue-discover", args="<input>")
Skill(skill="issue-discover", args="[FLAGS] \"<input>\"")

# 标志
-y, --yes              跳过所有确认（自动模式）
--action <type>        预选动作：new|discover|discover-by-prompt

# 阶段特定标志
--priority <1-5>       问题优先级（new 模式）
--perspectives <list>  逗号分隔的视角（discover 模式）
--external             启用 Exa 研究（discover 模式）
--scope <pattern>      文件范围（discover/discover-by-prompt 模式）
--depth <level>        standard|deep（discover-by-prompt 模式）
--max-iterations <n>   最大探索迭代次数（discover-by-prompt 模式）

# 示例
Skill(skill="issue-discover", args="https://github.com/org/repo/issues/42")                   # 从 GitHub 创建
Skill(skill="issue-discover", args="\"Login fails with special chars\"")                       # 从文本创建
Skill(skill="issue-discover", args="--action discover src/auth/**")                            # 多视角发现
Skill(skill="issue-discover", args="--action discover src/api/** --perspectives=security,bug") # 聚焦发现
Skill(skill="issue-discover", args="--action discover-by-prompt \"Check API contracts\"")      # Prompt 驱动发现
Skill(skill="issue-discover", args="-y \"auth broken\"")                                       # 自动模式创建
```

## 执行流程

```

   └─ 解析标志（--action, -y, --perspectives 等）和位置参数

   ├─ 提供了 --action 标志 → 直接路由
   ├─ 从输入自动检测：
```

## 核心规则

1. **动作选择优先**：在加载任何阶段之前必须确定动作
2. **单阶段加载**：只读取选定的阶段文档，不要加载所有阶段
3. **CLI 数据访问**：使用 `ccw issue` CLI 进行所有问题操作，不要直接读取文件
4. **内容保留**：每个阶段包含从原始命令中提取的完整执行逻辑
5. **自动检测输入**：智能输入解析减少了显式 --action 标志的需求

## 输入处理

### 自动检测逻辑

```javascript
function detectAction(input, flags) {
  // 1. Explicit --action flag
  if (flags.action) return flags.action;

  const trimmed = input.trim();

  // 2. GitHub URL → new
  if (trimmed.match(/github\.com\/[\w-]+\/[\w-]+\/issues\/\d+/) || trimmed.match(/^#\d+$/)) {
    return 'new';
  }

  // 3. Path pattern (contains **, /, or --perspectives) → discover
  if (trimmed.match(/\*\*/) || trimmed.match(/^src\//) || flags.perspectives) {
    return 'discover';
  }

  // 4. Short text (< 80 chars, no special patterns) → new
  if (trimmed.length > 0 && trimmed.length < 80 && !trimmed.includes('--')) {
    return 'new';
  }

  // 5. Long descriptive text → discover-by-prompt
  if (trimmed.length >= 80) {
    return 'discover-by-prompt';
  }

  // Cannot auto-detect → ask user
  return null;
}
```

## 核心指南

**数据访问原则**：Issues 文件可能非常大。为避免上下文溢出：

| 操作 | 正确做法 | 错误做法 |
|------|---------|---------|
| 列出问题（简要） | `ccw issue list --status pending --brief` | `Read('issues.jsonl')` |
| 读取问题详情 | `ccw issue status <id> --json` | `Read('issues.jsonl')` |
| 创建问题 | `echo '...' \| ccw issue create` | 直接文件写入 |
| 更新状态 | `ccw issue update <id> --status ...` | 直接文件编辑 |

**始终**使用 CLI 命令进行 CRUD 操作。**绝不**直接读取整个 `issues.jsonl`。

## 错误处理

| 错误 | 解决方案 |
|------|---------|
| 未检测到动作 | 显示 AskUserQuestion 和全部 3 个选项 |
| 无效动作类型 | 显示可用动作，重新提示 |
| 阶段执行失败 | 报告错误，建议手动干预 |
| 无匹配文件（discover） | 检查目标模式，验证路径是否存在 |
| Gemini 规划失败（discover-by-prompt） | 使用 qwen 重试 |
