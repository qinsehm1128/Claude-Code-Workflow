# 团队技能设计器

设计并生成具有基于角色路由的统一团队技能。所有团队成员调用 **一个** 技能，SKILL.md 通过 `--role` 参数将执行路由到特定角色的逻辑。触发词："design team skill", "create team skill", "team skill designer"。

# 团队技能设计器

用于创建统一团队技能的元技能，其中所有团队成员都调用 **一个** 技能，并带有基于角色的路由。生成一个完整的技能包，其中 `SKILL.md` 作为角色路由器，`roles/` 文件夹用于存放每个角色的具体执行细节。

## 核心创新：统一技能 + 角色路由器

**之前 (命令方法)**:
```
.claude/commands/team/
├── coordinate.md     →  /team:coordinate
├── plan.md           →  /team:plan
├── execute.md        →  /team:execute
├── test.md           →  /team:test
└── review.md         →  /team:review
```
→ 5个独立的命令文件，5个独立的技能路径

**之后 (统一技能方法)**:
```
.claude/skills/team-{name}/
├── SKILL.md          →  Skill(skill="team-{name}", args="--role=xxx")
├── roles/
│   ├── coordinator.md
│   ├── planner.md
│   ├── executor.md
│   ├── tester.md
│   └── reviewer.md
└── specs/
    └── team-config.json
```
→ 1个技能入口点，`--role` 参数路由到每个角色的执行逻辑

**协调者使用以下方式生成团队成员**:
```javascript
Task({
  prompt: `...调用 Skill(skill="team-{name}", args="--role=planner") 执行规划...`
})
```

## 核心设计模式

### 模式 1: 角色路由器 (统一入口点)

SKILL.md 解析 `$ARGUMENTS` 以提取 `--role`:
```
输入: Skill(skill="team-{name}", args="--role=planner")
  ↓ 解析 --role=planner
  ↓ 读取 roles/planner.md
  ↓ 执行规划者特定的5阶段逻辑
```

没有 `--role` → 错误 (角色是必需的，由协调者生成时设置)。

### 模式 2: SKILL.md 中的共享基础设施

SKILL.md 定义 **一次**，所有角色继承:
- 消息总线模式 (team_msg + CLI 备用方案)
- 任务生命周期 (TaskList → TaskGet → TaskUpdate)
- 团队名称和会话目录约定
- 错误处理和升级规则

### 模式 3: 角色文件 = 完整的执行细节

每个 `roles/{role}.md` 包含:
- 特定角色的5阶段实现
- 每个角色的消息类型
- 每个角色的任务前缀
- 完整的代码 (没有 `Ref:` 指回 SKILL.md)

### 模式 4: 批量角色生成

阶段 1 一次性收集 **所有** 角色 (不是一次一个):
- 团队名称 + 所有角色定义一次性完成
- 协调者总是被生成
- 工作角色作为一批被收集

### 模式 5: 自包含的规范

设计模式规范包含在本地的 `specs/` 目录中:
```
specs/team-design-patterns.md    # 基础设施模式 (8) + 协作索引
specs/collaboration-patterns.md  # 10个带收敛控制的协作模式
specs/quality-standards.md       # 质量标准
```

## 执行流程

```
阶段 0: 规范学习 (强制性)
   -> 阅读: specs/team-design-patterns.md
   -> 阅读: specs/collaboration-patterns.md
   -> 阅读: templates/skill-router-template.md + templates/role-template.md
   -> 阅读: 1-2个现有团队命令以供参考
   -> 输出: 内化的需求 (内存中)

阶段 1: 需求收集
   -> 参考: phases/01-requirements-collection.md
   - 收集团队名称和所有角色定义 (批量)
   - 对每个角色: 名称、职责、任务前缀、能力
   - 流水线定义 (任务链顺序)
   - 输出: team-config.json (团队级别 + 每个角色的配置)

阶段 2: 模式分析
   -> 参考: phases/02-pattern-analysis.md
   - 对每个角色: 找到最相似的现有命令
   - 对每个角色: 选择基础设施 + 协作模式
   - 对每个角色: 映射5阶段结构
   - 输出: pattern-analysis.json

阶段 3: 技能包生成
   -> 参考: phases/03-skill-generation.md
   - 生成 SKILL.md (角色路由器 + 共享基础设施)
   - 生成 roles/*.md (每个角色的执行细节)
   - 生成 specs/team-config.json
   - 输出: .claude/skills/team-{name}/ 完整的包

阶段 4: 集成验证
   -> 参考: phases/04-integration-verification.md
   - 验证角色路由器引用与角色文件匹配
   - 验证任务前缀在所有角色中是唯一的
   - 验证消息类型兼容性
   - 输出: integration-report.json

阶段 5: 验证
   -> 参考: phases/05-validation.md
   - 每个角色文件的结构完整性
   - 每个角色文件的模式合规性
   - 质量评分和交付
   - 输出: validation-report.json + 交付的技能包
```

## 比较: 命令设计器 vs 技能设计器

| 方面 | team-command-designer | team-skill-designer |
|--------|----------------------|---------------------|
| 输出 | N 个独立的 .md 命令文件 | 1 个技能包 (SKILL.md + roles/) |
| 入口点 | N 个技能路径 (/team:xxx) | 1 个技能路径 + --role 参数 |
| 共享基础设施 | 在每个命令中重复 | 在 SKILL.md 中定义一次 |
| 角色隔离 | 完全 (独立文件) | 完全 (roles/ 目录) |
| 协调者生成 | `Skill(skill="team:plan")` | `Skill(skill="team-{name}", args="--role=planner")` |
| 角色生成 | 一次一个角色 | 批量生成所有角色 |
| 模板 | command-template.md | skill-router-template.md + role-template.md |

## 错误处理

| 场景 | 解决方案 |
|----------|------------|
| 找不到规范 | 回退到内联的模式知识 |
| 角色名称冲突 | 使用 AskUserQuestion 请求重命名 |
| 任务前缀冲突 | 建议替代前缀 |
| 模板变量未解析 | 因特定变量名而失败 |
| 质量分数 < 60% | 使用额外上下文重新运行阶段 3 |

## 调试

| 问题 | 解决方案 |
|-------|----------|
| 生成的 SKILL.md 缺少路由器 | 检查 templates/skill-router-template.md |

| 集成检查失败 | 查看 phases/04-integration-verification.md |
| 质量分数低于阈值 | 查看 specs/quality-standards.md |
