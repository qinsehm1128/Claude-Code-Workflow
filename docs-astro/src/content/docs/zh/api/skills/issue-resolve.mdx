# Issue Resolve

带来源选择的统一问题解决流水线。通过 AI 探索规划问题方案、从制品转换、从头脑风暴会话导入，或组建执行队列。触发关键词："issue:plan"、"issue:queue"、"issue:convert-to-plan"、"issue:from-brainstorm"、"resolve issue"、"plan issue"、"queue issues"、"convert plan to issue"。

## 概览

| 属性 | 值 |
|------|-----|
| **名称** | `issue-resolve` |
| **工具** | `Task`, `AskUserQuestion`, `TodoWrite`, `Read`, `Write`, `Edit`, `Bash`, `Glob`, `Grep`, `Skill` |

## 参考

统一的问题解决流水线，编排来自多种来源的方案创建和用于执行的队列组建。

## 核心设计原则

1. **来源驱动路由**：AskUserQuestion 选择工作流，然后加载单个阶段
2. **渐进式阶段加载**：只读取选定的阶段文档
3. **CLI 优先数据访问**：所有问题/方案 CRUD 操作通过 `ccw issue` CLI 命令
4. **自动模式支持**：`-y` 标志跳过来源选择（默认为 Explore & Plan）

## 自动模式

当使用 `--yes` 或 `-y` 时：跳过来源选择，对问题 ID 使用 Explore & Plan，或对路径自动检测来源类型。

## 使用方法

```
Skill(skill="issue-resolve", args="<task description or issue IDs>")
Skill(skill="issue-resolve", args="[FLAGS] \"<input>\"")

# 标志
-y, --yes              跳过所有确认（自动模式）
--source <type>        预选来源：plan|convert|brainstorm|queue
--batch-size <n>       每批次最大问题数（plan 模式，默认：3）
--issue <id>           绑定到现有问题（convert 模式）
--supplement           为现有方案添加任务（convert 模式）
--queues <n>           并行队列数（queue 模式，默认：1）

# 示例
Skill(skill="issue-resolve", args="GH-123,GH-124")                              # 探索并规划问题
Skill(skill="issue-resolve", args="--source plan --all-pending")                 # 规划所有待处理问题
Skill(skill="issue-resolve", args="--source convert \".workflow/.lite-plan/my-plan\"")  # 转换制品
Skill(skill="issue-resolve", args="--source brainstorm SESSION=\"BS-rate-limiting\"")   # 从头脑风暴导入
Skill(skill="issue-resolve", args="--source queue")                              # 组建执行队列
Skill(skill="issue-resolve", args="-y GH-123")                                  # 自动模式，规划单个问题
```


## 核心规则

1. **来源选择优先**：在加载任何阶段之前必须确定来源
2. **单阶段加载**：只读取选定的阶段文档，不要加载所有阶段
3. **CLI 数据访问**：使用 `ccw issue` CLI 进行所有问题/方案操作，不要直接读取文件
4. **内容保留**：每个阶段包含从原始命令中提取的完整执行逻辑
5. **自动检测输入**：智能输入解析减少了显式 --source 标志的需求

## 输入处理

### 自动检测逻辑

```javascript
function detectSource(input, flags) {
  // 1. Explicit --source flag
  if (flags.source) return flags.source;

  // 2. Auto-detect from input content
  const trimmed = input.trim();

  // Issue IDs pattern (GH-xxx, ISS-xxx, comma-separated)
  if (trimmed.match(/^[A-Z]+-\d+/i) || trimmed.includes(',')) {
    return 'plan';
  }

  // --all-pending or empty input → plan all pending
  if (flags.allPending || trimmed === '') {
    return 'plan';
  }

  // SESSION="..." pattern → brainstorm
  if (trimmed.includes('SESSION=')) {
    return 'brainstorm';
  }

  // File/folder path → convert
  if (trimmed.match(/\.(md|json)$/) || trimmed.includes('.workflow/')) {
    return 'convert';
  }

  // Cannot auto-detect → ask user
  return null;
}
```

## 核心指南

**数据访问原则**：Issues 和 solutions 文件可能非常大。为避免上下文溢出：

| 操作 | 正确做法 | 错误做法 |
|------|---------|---------|
| 列出问题（简要） | `ccw issue list --status pending --brief` | `Read('issues.jsonl')` |
| 读取问题详情 | `ccw issue status <id> --json` | `Read('issues.jsonl')` |
| 更新状态 | `ccw issue update <id> --status ...` | 直接文件编辑 |
| 绑定方案 | `ccw issue bind <id> <sol-id>` | 直接文件编辑 |
| 批量方案 | `ccw issue solutions --status planned --brief` | 逐个查询循环 |

**输出选项**：
- `--brief`：最小字段的 JSON（编排器使用）
- `--json`：完整 JSON（仅 Agent 使用）

**始终**使用 CLI 命令进行 CRUD 操作。**绝不**直接读取整个 `issues.jsonl` 或 `solutions/*.jsonl`。

## 错误处理

| 错误 | 解决方案 |
|------|---------|
| 未检测到来源 | 显示 AskUserQuestion 和全部 4 个选项 |
| 无效来源类型 | 显示可用来源，重新提示 |
| 阶段执行失败 | 报告错误，建议手动干预 |
| 无待处理问题（plan） | 建议 `/issue:new` 先创建问题 |
| 无绑定方案（queue） | 建议先运行 plan/convert/brainstorm |
