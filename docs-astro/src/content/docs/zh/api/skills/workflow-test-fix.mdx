# 工作流测试修复 (Workflow Test Fix)

统一的测试修复编排器，将**测试规划生成**（阶段1）与**迭代测试周期执行**（阶段2）结合成一个端到端的单一流水线。它创建具有 L0-L3 渐进式测试层的测试会话，生成测试任务，然后通过自适应修复周期执行它们，直到通过率 ≥ 95% 或达到最大迭代次数。

## 关键设计原则

1.  **统一流水线**: 生成和执行是一个连续的工作流 - 无需手动交接。
2.  **纯粹编排器**: SKILL.md 仅进行协调 - 将所有执行细节委托给阶段文件。
3.  **自动继续**: 阶段1完成后 → 阶段2自动开始。
4.  **任务附加/折叠**: 在阶段执行期间附加子任务，完成后折叠。
5.  **渐进式阶段加载**: 阶段文档**仅**在该阶段执行时读取，而不是预先读取。
6.  **自适应策略**: 修复循环根据迭代上下文自动选择策略（保守/激进/外科手术式）。
7.  **质量门**: 通过率 ≥ 95%（考虑关键性）终止修复循环。
8.  **保留原始命令**: 阶段文件保留完整的原始命令内容和 Skill() 调用。

## 用法

```bash
# 完整流水线：生成 + 执行
/workflow:test-fix-gen "测试用户认证 API"
/workflow:test-fix-gen WFS-user-auth-v2

# 仅执行（从已有生成任务的测试会话恢复）
/workflow:test-cycle-execute
/workflow:test-cycle-execute --resume-session="WFS-test-user-auth"
/workflow:test-cycle-execute --max-iterations=15
```

## 自动模式

当使用 `--yes` 或 `-y` 时：自动选择第一个活动会话，跳过确认，成功时自动完成。

## 核心规则

1.  **立即开始**: 第一个动作是 TaskCreate 初始化，第二个动作是阶段 1（或对于仅执行的入口是阶段 2）。
2.  **无初步分析**: 在开始阶段之前不读取文件或收集上下文。
3.  **解析每个输出**: 从每个步骤的输出中提取所需数据以供下一步使用。
4.  **自动继续**: 阶段 1 → 阶段 2 自动进行（对于完整流水线入口）。
5.  **跟踪进度**: 使用任务附加/折叠模式动态更新 TaskCreate/TaskUpdate。
6.  **任务附加模型**: 在阶段中**附加**子任务，完成后**折叠**。
7.  **不要停止**: 连续工作流，直到满足质量门或达到最大迭代次数。
8.  **渐进式加载**: **仅**在即将执行该阶段时才读取阶段文档。
9.  **入口点路由**: `/workflow:test-fix-gen` → 阶段 1 + 阶段 2; `/workflow:test-cycle-execute` → 仅阶段 2。

## 输入处理

### test-fix-gen 入口 (完整流水线)
```
用户输入 → 检测类型:
  ├─ 以 "WFS-" 开始 → MODE=session, sourceSessionId=input
  ├─ 以 ".md" 结束    → MODE=prompt, description=Read(input)
```

### test-cycle-execute 入口 (仅阶段 2)
```

```

## 测试策略概述

渐进式测试层 (L0-L3):

| 层级 | 名称 | 关注点 |
|-------|------|-------|
| **L0** | 静态分析 | 编译、导入、类型、AI 代码问题 |
| **L1** | 单元测试 | 函数/类行为 (正常/异常/边界情况) |
| **L2** | 集成测试 | 组件交互、API 契约、失败模式 |
| **L3** | E2E 测试 | 用户旅程、关键路径 (可选) |

**质量阈值**:
- 代码验证 (IMPL-001.3): 零 CRITICAL 问题，零编译错误
- 最低覆盖率: 80% 行, 70% 分支
- 静态分析 (IMPL-001.5): 零关键反模式
- 通过率门槛: >= 95% (考虑关键性) 或 100%
- 最大修复迭代次数: 10 (默认, 可调)

## 策略引擎 (阶段 2)

| 策略 | 触发条件 | 行为 |
|----------|---------|----------|
| **保守** | 迭代 1-2 (默认) | 单一目标修复，完全验证 |
| **激进** | 通过率 >80% + 类似失败 | 批量修复相关问题 |
| **外科手术式** | 检测到回归 (通过率下降 >10%) | 最小化更改，关注回滚 |

选择逻辑和 CLI 后备链 (Gemini → Qwen → Codex) 在阶段 2 中有详细说明。

## Agent 角色

| Agent | 使用于 | 职责 |

| **编排器** | 两个阶段 | 路由入口，跟踪进度，传递上下文 |

## TodoWrite 模式

**核心概念**: 带有附加/折叠功能的动态任务跟踪，以实现实时可见性。

> **实现说明**: 阶段文件使用 `TodoWrite` 语法来描述概念上的跟踪模式。在运行时，这些通过允许工具列表中的 `TaskCreate/TaskUpdate/TaskList` 工具实现。将 `TodoWrite` 示例如下映射：
> - 初始列表创建 → 为每个项目 `TaskCreate`
> - 状态变更 → `TaskUpdate({ taskId, status })`
> - 子任务附加 → `TaskCreate` + `TaskUpdate({ addBlockedBy })`
> - 子任务折叠 → `TaskUpdate({ status: "completed" })` + `TaskUpdate({ status: "deleted" })` 用于折叠的子项

## 错误处理

### 阶段 1 (生成)

| 步骤 | 错误条件 | 操作 |
|------|----------------|--------|
| 会话创建 | 源会话未找到 (会话模式) | 返回带会话 ID 的错误 |
| 会话创建 | 没有已完成的 IMPL 任务 (会话模式) | 返回错误，源不完整 |
| 上下文收集 | 上下文收集失败 | 返回错误，检查源产物 |
| 分析 | Gemini 分析失败 | 返回错误，检查上下文包 |
| 任务生成 | 任务生成失败 | 重试一次，然后返回错误 |

### 阶段 2 (执行)

| 场景 | 操作 |
|----------|--------|
| 测试执行错误 | 记录日志，带错误上下文重试 |
| CLI 分析失败 | 后备: Gemini → Qwen → Codex → 手动 |
| Agent 执行错误 | 保存状态，用简化上下文重试 |
| 达到最大迭代次数 | 生成失败报告，标记为阻塞 |
| 检测到回归 | 回滚上次修复，切换到外科手术式策略 |
| 检测到卡住的测试 | 继续使用替代策略，并记录 |

## 提交策略 (阶段 2)

在关键检查点自动提交:
1.  **成功迭代后** (通过率增加): `test-cycle: iteration N - strategy (pass: old% → new%)`
2.  **回滚前** (检测到回归): `test-cycle: rollback iteration N - regression detected`

## 完成条件

| 条件 | 通过率 | 操作 |
|-----------|-----------|--------|
| **完全成功** | 100% | 自动完成会话 |
| **部分成功** | >= 95%, 所有失败项为低关键性 | 自动批准并附审查说明 |
| **失败** | 最大迭代后 `< 95%` | 失败报告，标记为阻塞 |

## 完成后扩展

完成后，询问用户是否要扩展为 issue (测试/增强/重构/文档)。所选项调用 `/issue:new "{summary} - {dimension}"`。

## 协调器清单

### 阶段 1 (test-fix-gen)
- [ ] 检测输入类型 (会话 ID / 描述 / 文件路径)
- [ ] 在任何执行前初始化 TaskCreate
- [ ] 读取阶段 1 文档，执行所有 5 个内部步骤
- [ ] 从步骤输出中解析 testSessionId，存储在内存中
- [ ] 验证所有阶段 1 输出 (4个任务 JSON, IMPL_PLAN.md, TODO_LIST.md)
- [ ] 折叠阶段 1 任务，自动继续到阶段 2

### 阶段 2 (test-cycle-execute)
- [ ] 读取阶段 2 文档
- [ ] 加载会话、任务、迭代状态
- [ ] 顺序执行初始任务
- [ ] 从 test-results.json 计算通过率
- [ ] 如果 `pass_rate < 95%`：进入修复循环
- [ ] 跟踪迭代次数、卡住的测试、回归
- [ ] 如果 pass_rate >= 95% 或达到最大迭代次数: 完成
- [ ] 生成完成总结
- [ ] 提供完成后扩展选项
