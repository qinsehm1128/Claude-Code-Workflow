# /ccw-debug

调试协调器 - 分析问题、选择调试策略，并在主进程中执行调试工作流。

## 概述

`/ccw-debug` 命令通过分析问题描述、选择适当的调试策略并执行针对性的命令链来编排调试工作流。

**参数**：
- `--mode <mode>`：调试模式 (cli, debug, test, bidirectional)
- `--yes|-y`：跳过确认提示
- `"bug description"`：要调试的问题（必填）

**核心概念**：调试单元 - 将命令分组为逻辑单元，用于不同的根因分析策略。

## 特性

- **问题分析** - 提取症状、发生模式、受影响组件
- **策略选择** - 基于关键词和复杂度自动选择
- **调试单元** - 4 种调试模式适用于不同场景
- **并行执行** - 双向模式用于复杂问题
- **状态跟踪** - TODO 和状态文件跟踪

## 用法

```bash
# 自动选择模式（基于关键词检测）
/ccw-debug "Login timeout error"

# 显式选择模式
/ccw-debug --mode cli "Quick API question"
/ccw-debug --mode debug "User authentication fails"
/ccw-debug --mode test "Unit tests failing"
/ccw-debug --mode bidirectional "Complex multi-module issue"

# 跳过确认
/ccw-debug --yes "Fix typo in config"
```

## 调试模式

### CLI 模式
**适用于**：快速分析、简单问题、早期诊断

**命令链**：
```
ccw cli --mode analysis --rule analysis-diagnose-bug-root-ause
```

**特点**：
- 仅分析
- 不修改代码
- 返回发现和建议

### Debug 模式
**适用于**：标准 Bug 诊断和修复

**命令链**：
```
/workflow:debug-with-file
/workflow:test-fix-gen
/workflow:test-cycle-execute
```

**特点**：
- 假设驱动的调试
- 测试生成
- 迭代修复

### Test 模式
**适用于**：测试失败、测试验证

**命令链**：
```
/workflow:test-fix-gen
/workflow:test-cycle-execute
```

**特点**：
- 以测试为中心
- 在测试中修复
- 迭代直到通过

### 双向模式
**适用于**：需要多视角的复杂问题

**命令链**（并行）：
```
/workflow:debug-with-file  ∥  /workflow:test-fix-gen  ∥  /workflow:test-cycle-execute
                            ↓
                      合并发现
```

**特点**：
- 并行执行
- 多视角分析
- 合并发现

## 调试单元

| 单元名称 | 命令 | 用途 |
|-----------|----------|---------|
| **快速分析** | ccw cli (analysis) | 快速诊断 |
| **标准调试** | debug-with-file → test-fix-gen → test-cycle-execute | 完整调试循环 |
| **测试修复** | test-fix-gen → test-cycle-execute | 以测试为中心的修复 |
| **全面诊断** | (debug ∥ test ∥ test-cycle) → merge | 多视角分析 |

## 执行流程

```
用户输入: "bug description"
    ↓
阶段 1: 分析问题
    ├─ 提取: description, error_type, clarity, complexity, scope
    └─ 如果 clarity < 2 → 阶段 1.5: 澄清问题
    ↓
阶段 2: 选择调试策略并构建命令链
    ├─ 检测模式: cli | debug | test | bidirectional
    ├─ 基于模式构建命令链
    └─ 双向模式使用并行执行
    ↓
阶段 3: 用户确认（可选）
    ├─ 显示调试策略
    └─ 允许更改模式
    ↓
阶段 4: 设置 TODO 跟踪和状态文件
    ├─ 创建 CCWD 前缀的 TODO
    └─ 初始化 .workflow/.ccw-debug/{session_id}/status.json
    ↓
阶段 5: 执行调试链
    ├─ 顺序执行: 按顺序执行命令
    ├─ 双向模式: 并行执行调试+测试
    ├─ CLI 模式: 展示发现，询问是否升级
    └─ 合并发现（双向模式）
    ↓
更新状态和 TODO
```

## 模式检测

| 关键词 | 检测到的模式 |
|----------|---------------|
| quick, simple, question, what, how | cli |
| bug, error, fail, crash, timeout | debug |
| test, unit test, coverage, assertion | test |
| complex, multiple, module, integration | bidirectional |

## 调试流水线示例

| 问题 | 模式 | 流水线 |
|-------|------|----------|
| "Login timeout error (quick)" | cli | ccw cli → analysis → (升级或完成) |
| "User login fails intermittently" | debug | debug-with-file → test-gen → test-cycle |
| "Authentication tests failing" | test | test-fix-gen → test-cycle-execute |
| "Multi-module auth + db sync issue" | bidirectional | (debug ∥ test) → 合并发现 |

**图例**：`∥` = 并行执行

## 相关命令

- **/workflow:debug-with-file** - 假设驱动的调试
- **/workflow:test-fix-gen** - 测试修复生成
- **/workflow:test-cycle-execute** - 测试循环执行
- **/ccw** - 主工作流协调器

## 注意事项

- **自动模式检测** 基于关键词
- **调试单元** 确保完整的调试里程碑
- **TODO 跟踪** 使用 CCWD 前缀
- **状态文件** 存储在 `.workflow/.ccw-debug/{session}/`
- **并行执行** 用于双向模式
- **合并发现** 结合多视角分析
- **升级支持** 从 CLI 模式升级到其他模式
